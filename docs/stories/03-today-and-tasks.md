# Story 03：Today 与任务

## 目标

让用户每天打开 Mainline 时可以看见完整安排，并手动创建、修改、认领、完成和删除任务；系统明确区分今天唯一主线与其他可选推进。

## 范围

- SQLite 新增任务迁移和任务 Repository；
- TypeBox 定义任务、创建、修改、日期查询与 API 响应契约；
- 提供任务列表、创建、修改、开始、普通完成和删除 API；
- 同一天只允许一个进行中或计划中的主线任务；
- 提供移动端 Today 页面、任务录入面板和任务动作反馈；
- 支持主线、支线、成长、日常四个归属，及一次性、重复、挑战、事件四种形式；
- 支持上午、下午、晚上和任意时间四种时间段。

## 非目标

- 不由 AI 创建或修改任务；
- 不处理重要任务的结果报告、经验、奖励、惩罚或未完成结算；
- 不实现目标章节和任务归属目标；
- 不实现跨天自动迁移或重复任务自动生成。

## 核心规则

1. 任务事实只能由用户的 API 操作建立或修改；AI 后续只能提交待确认提案。
2. 每日有效主线唯一：`planned` 与 `in_progress` 状态均计入约束。
3. 普通任务可从计划中认领为进行中，再标记完成；完成记录不能在本故事被删除或重新编辑。
4. 未完成任务不会自动滚入明天，用户必须主动修改其日期或状态。
5. 任务保存到 SQLite；Web 不保存任务正文作为本地事实源。

## 验收标准

1. 用户可安排某天的主线、支线、成长或日常任务，并填写内容、形式和时间段。
2. 创建或修改第二条同日有效主线时 API 返回可理解的冲突错误。
3. 用户可查看所选日期的任务，开始、普通完成、修改或删除未完成任务。
4. 完成的任务显示为已完成，无法被本故事的删除和编辑入口篡改。
5. Today 在无任务、加载失败、冲突和动作成功时均有中文反馈。
6. API 单元测试覆盖 CRUD、主线唯一性、状态流转和日期校验；Web 单测覆盖核心 Today 反馈。
7. 通过 `pnpm check`、浏览器移动端验收和 `git diff --check` 后独立提交。

## 实现备注

- “重要任务完成后填写结果”的流程将在 Story 05 加入，避免当前普通完成语义被混淆。
- 当前任务表预留完整生命周期状态值，但 UI 只开放本故事需要的 `planned`、`in_progress`、`completed` 动作。
- 数据库层用部分唯一索引作为最终约束，服务层再提供可读的冲突信息。
