# Story 04：AI 提案与现实中断

## 目标

让 AI 在用户主动请求时辅助规划任务、识别任务归属和回应现实中断，同时保持“用户决定、AI 提案、事实另行保存”的边界。

## 范围

- 从根目录 `.env` 仅在服务端读取 DeepSeek Key 与模型配置；
- 通过 DeepSeek JSON 模式生成任务规划提案和现实中断建议；
- 校验模型输出并保存为本地 SQLite 待确认提案；
- 支持从本地重新查看待确认提案、接受或忽略提案；
- 任务录入面板可请求 AI 规划，并仅在用户接受后回填建议字段；
- Today 可记录现实中断并查看一条非强制性建议；
- 所有 AI 响应不直接创建、修改、删除或完成任务。

## 非目标

- 不把 Key、模型响应原文或用户图片发送到浏览器；
- 不让 AI 自动执行任务数据写入或状态变更；
- 不让 AI 评判经验、奖励、惩罚或结果质量；
- 不实现多轮对话、自动记忆检索或后台 Agent。

## 核心规则

1. AI 调用必须由用户的明确点击触发，且 Key 只存在于本机服务端环境。
2. 模型输出先通过 TypeBox 对应的运行时结构校验，失败时只能返回可理解错误，不能写入提案表。
3. 提案以 `pending` 状态存储；接受或忽略是用户事实，但接受本身不变更任务。
4. 任务规划提案被接受后只可回填到浏览器表单，用户仍必须点击“安排任务”才会创建任务。
5. 现实中断只提出保留、缩小、改期或暂停的建议；实际调整仍由用户选择并手动执行。

## 验收标准

1. 未设置 `DEEPSEEK_API_KEY` 时，AI 入口显示明确的本机配置指引且不暴露 Key。
2. 配置后服务端以 JSON 模式调用 DeepSeek，校验成功才创建 SQLite 提案。
3. 模拟 Provider 的测试覆盖任务规划、现实中断、接受、忽略和非法模型输出；未配置 Key 的运行时路径返回 `AI_NOT_CONFIGURED`。
4. 任务录入中，接受 AI 建议后只更新表单字段，不自动创建任务。
5. Today 中，提交现实中断后用户可以查看和确认建议，不产生自动状态变更。
6. 通过 `pnpm check`、前端组件交互测试和 `git diff --check` 后独立提交。

## 实现备注

- DeepSeek API 使用 `/chat/completions`、`response_format: { type: "json_object" }` 和 `deepseek-v4-flash` 默认模型。
- 不配置 Key 时可继续使用所有非 AI 的本地任务功能。
- 图片凭证永远不进入本故事的 AI 调用。
- 浏览器的 AI 提案 API 响应与第三方模型输出均经 TypeBox 运行时校验；后者无法通过校验时不入库。
