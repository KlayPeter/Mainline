# Story 02：本地数据基础

## 目标

让 Mainline 的本地 API 拥有可迁移、可重启验证的 SQLite 存储基础，为后续任务、目标与复盘提供统一数据归属。

## 范围

- 使用 Node.js 内建 `node:sqlite` 创建本地 SQLite 文件；
- 为数据库提供最小迁移执行器与迁移记录表；
- 创建本地安装记录，确认数据库首次初始化时间；
- 提供只报告驱动与迁移数量的存储状态接口；
- 用共享 TypeBox 契约约束存储状态响应；
- 为内存数据库和真实临时文件数据库编写回归测试。

## 非目标

- 不创建任务、目标、复盘、奖励或 AI 业务表；
- 不向浏览器暴露数据库路径、SQL 或任意用户记录；
- 不增加 ORM、云数据库、账号或同步。

## 验收标准

1. 默认运行时在工作区 `data/mainline.sqlite` 建立本地数据库，且可通过环境变量覆写位置。
2. 同一个数据库第二次启动不会重复执行已经记录的迁移。
3. `GET /system/storage` 只返回 SQLite 可用状态与迁移数。
4. API 使用 TypeBox 约束该接口响应；浏览器仍不会读取数据库。
5. 内存与临时文件数据库的迁移回归测试均通过。
6. 数据库功能具备 Owner `FEATURE.md`，并登记至功能目录。
7. 本故事在独立提交中完成。

## 实现备注

- Node.js 版本基线为 22，因此 `node:sqlite` 可作为最小本地驱动使用。
- 迁移在 Adapter 内串行执行；领域功能只会通过后续 Repository 使用它。
- 本故事不预先猜测任务表字段，真正需要表时再新增独立迁移。
