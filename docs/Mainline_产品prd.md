# Mainline 产品需求文档

**版本：V1.0**
**状态：首版本地 MVP 需求基线**
**目标用户：产品创建者本人，后续扩展到有成长意愿但执行不稳定的年轻用户**

## 1. 产品目标

Mainline 将用户当前的人生状态、多个领域目标和每天的行动连接起来。首版要让用户完成以下闭环：

```text
初始问卷
  → 建立人生状态、领域章节和目标
  → 用户录入任务
  → AI 提出分类、拆解和排程建议
  → 用户确认完整安排
  → 专注执行并记录中断
  → 提交结果或处理未完成任务
  → 获得经验、兑现奖励或惩罚
  → 每日/每周复盘
  → 更新计划和长期记忆
```

首版只在本机运行，用于连续自用验证，不上线。

## 2. 用户画像与场景

### 2.1 当前用户

- 应届毕业，处于从学校过渡到职场的阶段；
- 希望适应工作，同时学习 AI Coding 和 Agent 开发；
- 希望持续写公众号并积累读者；
- 有健身需求；
- 喜欢制定计划，但容易从计划本身获得满足，执行不足；
- 会被加班、疲惫、游戏和短视频干扰；
- 容易忘记记录，也很少主动回看；
- 希望通过明确的奖励、惩罚和进展反馈加强行动动力。

### 2.2 核心使用场景

1. 打开系统查看今天完整安排和唯一的今日主线任务。
2. 手动录入工作任务及其具体内容，请 AI 协助归类和排程。
3. 将较大的学习目标拆成阶段、里程碑和可执行任务。
4. 执行任务时计时，遇到变化时记录“发生了什么”。
5. 完成普通任务，或为重要任务提交结果报告。
6. 任务未完成时明确处理去向并执行契约。
7. 在每天和每周结束时复盘真实进展与干扰。

## 3. 范围

### 3.1 首版必须支持

- 5～10 分钟初始问卷；
- 人生状态、五个领域、领域章节；
- 主线目标、支线目标、阶段、里程碑和任务；
- 任务增删改查及完整安排确认；
- AI 分类、拆解、排程、超载提示和解释；
- 今日任务面板和今日主线任务；
- 固定日程、时间段和任务冲突提示；
- 专注执行、正计时、番茄计时、暂停和中断记录；
- 普通完成、结果报告、待处理任务；
- 经验、能力线和简洁成长档案；
- 奖励池、奖励刷新、承诺和多种惩罚；
- 奖惩凭证本地保存；
- 每日复盘和每周复盘；
- 长期记忆查看、修改和删除；
- 本地通知设置；
- 完整数据导入、导出和备份提醒；
- DeepSeek V4 Flash 接入及无 AI 降级。

### 3.2 首版不做

- 注册、登录、云同步和多用户；
- 线上部署和线上数据库；
- 社交、排行榜、公会和好友协作；
- 关系与财富领域；
- 复杂装备、金币商店、战斗或角色养成；
- AI 识别或审核凭证图片；
- 复杂月报、年度报告和大型数据看板；
- 原生 App、微信小程序和手表端；
- 自动读取公司系统、日历或第三方任务平台。

## 4. 核心数据模型

### 4.1 人生状态 Life State

描述用户当前总体处境。首版同时只有一个当前人生状态。

字段：

- 名称；
- 描述；
- 开始日期；
- 预计结束日期；
- 当前状态。

示例：“应届毕业第一阶段——过渡期”，预计持续 3～4 个月。

### 4.2 领域 Domain

首版固定五个领域：职业、学习、创作、健康、生活。每个领域可以拥有一个当前章节和历史章节。

### 4.3 章节 Chapter

章节是一段可结束的领域阶段。字段包括：

- 所属领域；
- 标题和说明；
- 开始、预计结束和实际结束日期；
- 成功条件；
- 关键里程碑；
- 状态：草稿、进行中、已完成、已暂停、已结束。

章节进展由里程碑和结果驱动，不能按任务数量自动计算。

### 4.4 目标 Goal

目标分主线目标和支线目标。每个领域最多同时有 1 个进行中的主线目标和 2 个进行中的支线目标。

全局允许多个领域主线，但只突出 1～2 个当前焦点目标。焦点可随时间和现实情况修改。

字段包括：

- 所属领域和章节；
- 主线或支线；
- 是否为当前焦点；
- 标题、动机和成功条件；
- 期限、预计投入和状态；
- 阶段、里程碑和真实进展。

### 4.5 任务 Task

任务是最小执行对象。任务必须包含标题，可以选填详细内容。

任务维度：

| 维度 | 取值 |
| --- | --- |
| 目标归属 | 主线目标、支线目标、无目标 |
| 行动形式 | 一次性、日常、挑战、事件 |
| 日内优先级 | 今日主线、重要、普通 |
| 状态 | 计划中、进行中、已暂停、被中断、已完成、未完成、待处理、已放弃、已结束 |
| 结果要求 | 普通完成、需要结果报告 |
| 契约 | 无、已设置 |

任务还可包含日期、起止时间、预计时长、期限、前置任务、步骤、奖励、惩罚和提醒。

## 5. 初始问卷

### 5.1 目标

问卷用 5～10 分钟了解用户，使 AI 第一次规划就具有现实约束。所有问题都可以跳过，但系统会提示：跳过过多会降低建议质量，之后仍可补充。

### 5.2 问卷内容

1. 当前人生状态及持续时间。
2. 职业、学习、创作、健康、生活的现状。
3. 最近最重要的目标和必须完成的事情。
4. 固定工作、通勤、睡眠、运动等时间段。
5. 可投入时间、精力高低时段和休息需求。
6. 常见干扰、计划失败方式和不愿牺牲的底线。
7. 喜欢的现实奖励、娱乐方式和预算上限。
8. 能接受的金钱、权限和额外行动惩罚。
9. 身体状况及禁止使用的身体类惩罚。
10. 希望发展的能力线。
11. 通知和安静时间偏好。

### 5.3 AI 初始建议

AI 根据问卷生成：

- 人生状态草稿；
- 各领域章节草稿；
- 主线、支线和当前焦点建议；
- 固定日程和可用时间；
- 奖励池、惩罚白名单和预算；
- 长期记忆草稿。

用户可以逐项修改。只有用户点击确认后，系统才保存。

## 6. 任务创建与 AI 规划

### 6.1 用户输入

任务从用户输入开始。最少输入标题；推荐输入内容、期望完成时间和完成标准。

工作任务由用户手动录入，AI 不猜测公司安排。

### 6.2 AI 输出

AI 返回一份可编辑的完整建议：

- 推荐领域、章节和目标归属；
- 主线、支线或无目标判断及理由；
- 一次性、日常、挑战或事件判断；
- 是否需要结果报告；
- 步骤和预计时长；
- 推荐时间段；
- 与现有日程的冲突；
- 当天超载风险和完成概率；
- 奖励、承诺和惩罚建议；
- 对目标进展的可能贡献。

### 6.3 用户确认

系统必须先展示完整安排。用户可以增加、删除、修改任意字段，也可以忽略 AI 建议。保存前不得改变正式数据。

任务数不设硬上限。AI 在总时长、精力或冲突不合理时明确警告，用户仍可强制保存。

## 7. 今日任务面板

每日首次进入时展示 1～2 秒的“载入今日”，随后进入任务面板，不要求晨间确认。

任务面板优先展示：

1. 当前人生状态和一句当日提示；
2. 当前焦点目标；
3. 唯一的今日主线任务；
4. 按时间排列的完整任务；
5. 待处理、临近期限和发生冲突的任务；
6. “添加任务”和“发生了什么”两个主要入口。

页面默认不展示复杂统计、完整属性面板、AI 长文和无关导航。

## 8. 固定日程与排程

用户可以维护工作、通勤、睡眠、健身等固定时间段，并随时修改。

AI 排程必须：

- 避开固定日程冲突；
- 计算当天已承诺总时长；
- 考虑用户精力时段；
- 保留休息和缓冲；
- 优先保护今日主线任务；
- 在学习、创作等任务挤压睡眠或工作时给出明确警告。

AI 只提出安排，用户确认后才保存。

## 9. 专注执行

任务开始后进入专注页面。页面只保留：任务标题、当前步骤、剩余或已用时间、暂停、完成和“发生了什么”。

计时支持：

- 正计时；
- 番茄计时，自定义专注与休息长度。

任务开始后锁定契约奖励，禁止刷新。

### 9.1 中断

用户可以随时记录中断：

- 临时工作；
- 他人请求；
- 身体疲惫；
- 游戏或短视频；
- 环境问题；
- 其他原因。

记录包含发生时间、描述、影响和处理方式。AI 可以在复盘时识别模式，但不能替用户修改任务。

## 10. 完成与结果报告

### 10.1 普通完成

普通任务一键完成，系统按确定规则发放基础经验，并记录时间。

### 10.2 需要结果报告

以下任务默认需要结果报告：

- 今日主线任务；
- 里程碑；
- 项目交付；
- 课程阶段；
- 公开发布的文章；
- 承诺任务；
- 用户手动标记的重要任务。

用户填写：

- 做出了什么；
- 结果或凭据说明；
- 实际投入；
- 自评：低于预期、达到预期、超出预期；
- 下一步。

AI 根据预先确定的完成标准，在规则允许的范围内建议：

- 经验调整；
- 能力线分配；
- 里程碑和目标进展；
- 后续任务。

用户确认后才记账和更新进展。

## 11. 未完成与待处理

任务到期未完成后进入待处理，不自动滚动。

用户必须选择：

- 改期；
- 修改内容或缩小范围；
- 暂停；
- 放弃；
- 结束并记录原因。

普通任务失去本次奖励。存在契约时，系统按契约结算惩罚。

用户可在期限前重新规划。默认每月有 2 次免费契约改期；用完后再次改期会产生事先确认的小额代价。过期未完成执行完整惩罚。所有变更留下记录。

## 12. 日常任务

日常任务支持跳过。连续或频繁跳过后，AI 可以建议降低频率、调整时间、缩小任务或暂停习惯。用户确认后才修改。

日常任务不以保持连续天数为唯一目标，系统更关注是否适合当前生活节奏。

## 13. 经验与能力线

### 13.1 经验规则

- 经验只能获得，不能消费或扣除；
- 每次经验变化都记录来源；
- 普通任务使用固定基础经验；
- 重要任务允许 AI 在预设区间内调整；
- 用户确认后才写入经验账本；
- 取消或修改任务不能删除已经由真实完成获得的经验。

### 13.2 能力线

首版能力线由问卷和目标生成，可由用户修改。当前重点示例：

- AI Coding 工程能力；
- Agent 开发能力；
- 工作独立交付能力；
- 写作与内容创作能力；
- 健康与体能。

成长页只展示等级、经验、能力线、里程碑和历史记录，不做复杂角色面板。

## 14. 奖励系统

### 14.1 奖励池

奖励由用户在问卷或设置中预先批准，并包含类型、成本、可用频率和适用任务等级。

类型包括：

- 小额实物：可乐、零食等；
- 娱乐权限：无负担刷手机两小时、玩游戏两小时；
- 中长期实物：鞋子等；
- 自定义奖励。

大额奖励只用于章节、长期目标或重要里程碑。

### 14.2 AI 选取与刷新

AI 从用户批准且符合预算的奖励中选择，不得创造未授权消费。

- 新奖励可免费刷新 1 次；
- 之后刷新消耗 1 次“改运次数”；
- 每周复盘补充 1 次；
- 重要里程碑可额外补充 1 次；
- 最多保存 3 次；
- 接受并开始任务后奖励锁定。

用户不能直接编辑已生成奖励，但可以放弃契约后重新创建。

## 15. 惩罚与凭证

### 15.1 惩罚类型

- 金钱：在 24 小时内转给父母或朋友；
- 权限：取消娱乐或奖励；
- 额外行动：完成用户预先批准的行动。

### 15.2 安全规则

- 用户必须在任务开始前明确接受；
- 身体类行动必须来自白名单并设置上限；
- 生病、受伤或身体不适时必须换成非身体惩罚；
- 禁止伤害、极端运动、禁食、剥夺睡眠和违法行为；
- AI 只能从批准范围内建议，不能提高强度。

### 15.3 兑现

用户在 24 小时内标记兑现，并可上传图片凭证。图片只保存在本机，只供用户回看，不发送给 AI。AI 不审核真实性。

## 16. 复盘

### 16.1 每日复盘

每日复盘应在一分钟内完成，包含：

- 今天真正推进了什么；
- 哪件事没有按计划发生；
- 主要中断和状态；
- 奖励或惩罚是否需要兑现；
- 明天最值得优先处理的事项。

### 16.2 每周复盘

每周复盘包含：

- 各领域和焦点目标的实际进展；
- 计划时间与实际投入差异；
- 重复出现的中断；
- 过度安排、频繁跳过和拖延模式；
- 奖惩兑现情况；
- AI 调整建议；
- 下周焦点和固定日程调整。

AI 只生成总结和建议。用户确认后才能创建任务、修改目标或写入长期记忆。

## 17. 长期记忆

长期记忆包括：

- 当前人生状态和长期方向；
- 固定日程与现实限制；
- 奖励、惩罚和通知偏好；
- 常见干扰与执行模式；
- 被验证有效或无效的策略；
- 用户明确要求记住的内容。

每条记忆包含来源、创建时间和最近更新时间。用户可以查看、修改和删除。AI 新增或修改记忆前必须获得确认。

## 18. 通知

首版支持本地浏览器/PWA通知：

- 任务开始前；
- 今日主线任务尚未开始；
- 临近期限；
- 中断后仍未恢复；
- 每日复盘未完成；
- 惩罚凭证即将到期；
- 每周数据备份。

每类通知可单独关闭，并遵守用户设置的安静时间。首版本地通知在应用未运行时可能受浏览器限制，界面需明确说明。

## 19. 本地数据与 AI

- SQLite 是结构化数据的唯一事实来源；
- 图片保存在本地文件目录，SQLite 保存元数据和路径；
- 浏览器只保存会话和临时缓存；
- DeepSeek API Key 保存在本地服务的 `.env`；
- 浏览器不能读取 API Key；
- AI 只接收完成当前请求所需的文字上下文；
- 凭证图片不发送给 AI；
- AI 不可用时，任务、计时、完成、奖惩、复盘和数据管理仍可使用；
- 用户可以导出包含 SQLite 数据和图片的完整备份包，并恢复到本机。

## 20. 示例目标线

### 20.1 职业领域

- 人生状态：应届毕业后的过渡期，3～4 个月；
- 职业章节：从职场新人到能够独立承担工作；
- 本章成功条件：能够独立承担工作，记录至少 3 次来自同事或领导的明确认可；
- 长期里程碑：年底争取调薪；
- 可控进展：独立交付任务、掌握核心流程、获得明确反馈、主动进行阶段沟通。

年底调薪不作为当前 3～4 个月章节的强制完成条件，因为它超出章节周期，也不完全由用户控制。

### 20.2 创作领域

- 目标：一个月发布 15 篇长短混合的公众号内容，或获得 50 名以上新关注者；
- 当前优先级：高；
- 里程碑：选题池、首批发布、阶段数据检查和月末总结。

### 20.3 学习领域

- 目标：完成一套 Agent 学习路线，产出完整 Agent 项目，并能以教程、讲解或视频形式教学；
- 重点能力：AI Coding 工程能力、Agent 开发能力；
- 期限：先按 45 天路线规划，可根据实际投入调整；
- 路线：SDD 学方法 → Deep Agents 学工程 → Hello-Agents 补基础 → Agent-Learning-Hub 查缺口 → 完成 Agent 项目和教学产出；
- Agent 学习可以暂停或降级，不能挤压工作主线和基本休息。

### 20.4 健康领域

- 健身属于成长型日常任务；
- 可以跳过；
- 频繁跳过后，AI 提议修改频率、时间或任务量；
- 用户确认后才改变安排。

## 21. 验收标准

首版达到以下条件才算逻辑完整：

1. 新用户可以从问卷建立人生状态、领域章节、目标和偏好。
2. 用户可以创建工作、学习、创作和健康任务。
3. AI 能提出结构化建议，用户能编辑并确认。
4. 今日面板能显示完整安排和唯一今日主线任务。
5. 用户可以开始、暂停、中断、完成和处理未完成任务。
6. 普通任务与结果任务拥有不同完成流程。
7. 经验、奖励、刷新、承诺和惩罚能形成闭环。
8. 用户可以上传并本地查看惩罚凭证。
9. 每日和每周复盘能根据真实数据生成建议。
10. 用户可以管理长期记忆。
11. DeepSeek 不可用时，基础功能仍可运行。
12. 用户可以完整导出并恢复数据库和图片。

## 22. 自用验证

连续使用 14 天，检查：打开频率、真实任务数量、中断记录、结果报告、承诺兑现、奖惩兑现、复盘完成率和超载改善情况。

最重要的判断只有一个：用户是否愿意每天打开 Mainline，并因此比以前更认真地完成自己决定的事情。
