# Mainline 前端重构实施规划

**版本：V1.0**
**状态：实施前规划**
**范围：全新前端、完整 MVP 体验、本地运行**

## 1. 规划结论

现有 `index.html` 和 `redesign.css` 不作为新设计基础。实施时先将它们归档为旧稿，再从空白 React 工程开始。

新前端必须先跑通三条体验路径：

1. 安排并完成普通任务。
2. 使用 AI 规划重要任务并提交结果报告。
3. 任务被现实打断后调整计划、处理违约并完成复盘。

首版追求完整、安静、可持续使用，不追求页面数量和装饰效果。

## 2. Skill 使用策略

本次设计结合三套前端 Skill，但它们承担不同职责。

### 2.1 UI UX Pro Max

负责产品结构和可用性：

- 移动端优先；
- 底部导航和安全区域；
- 表单渐进披露；
- 触控尺寸、键盘、焦点和对比度；
- 加载、空白、错误和离线状态；
- React 状态与性能约束。

### 2.2 Taste Skill

Taste Skill 明确不主导复杂产品界面，因此只使用它的反模板化规则：

- 避免 AI 紫色、满屏玻璃、等宽三卡和装饰性状态点；
- 卡片只表达真实层级；
- 统一配色、圆角和图标；
- 动效必须表达状态变化；
- 设计前声明视觉判断和三个设计刻度；
- 交付前执行反 AI 痕迹检查。

### 2.3 Frontend Design

负责形成独特的视觉概念，并把产品功能、中文排版和情绪体验整合成一个系统。

## 3. 设计判断

> Reading this as: 一款给年轻个人用户每天使用的移动任务产品，采用安静、深色、克制而有现实重量的语言，接近“个人任务存档舱”，不接近游戏 HUD 或数据后台。

设计模式为全新重构。旧页面的视觉、布局、文案和导航都不继承。

### 3.1 设计刻度

| 刻度 | 数值 | 含义 |
| --- | --- | --- |
| `DESIGN_VARIANCE` | 6/10 | 有识别度，但不牺牲任务可读性 |
| `MOTION_INTENSITY` | 4/10 | 使用状态过渡，不使用炫技滚动 |
| `VISUAL_DENSITY` | 3/10 | 每屏只保留当前行动需要的信息 |

### 3.2 记忆点

Mainline 的记忆点不是霓虹、经验条或游戏图标，而是“今天只有一个最值得推进的任务”。

首页将这个任务表现为一个占据主要视觉空间的行动面板。其他任务退到时间轨迹中。用户每次打开都先看到行动，再看到系统。

## 4. 视觉系统方向

### 4.1 主题

首轮视觉验收以深色主题为主，同时从一开始定义亮色令牌。默认跟随系统，用户可以手动切换。

深色主题：

- 背景采用冷调石墨黑，不使用纯黑；
- 主文字采用略带灰度的白，不使用纯白；
- 表面只比背景提高一个明度层级；
- 主强调色采用低饱和信号橙，表达行动、聚焦和确认；
- 成功、警告、危险使用语义色，并始终配合文字或图标。

亮色主题：

- 背景采用冷白和浅灰；
- 保持相同的信号橙；
- 不使用米黄、黄铜和复古纸张配色；
- 保持与深色主题相同的信息层级。

### 4.2 字体

- 中文正文和标题：自托管 `Noto Sans SC`；
- 时间、计时器和数据：`Geist Mono` 或等宽数字特性；
- 正文移动端不小于 16px；
- 使用字号、字重和留白建立层级，不混用装饰字体；
- 数字使用等宽字形，避免计时过程中跳动。

### 4.3 形状

定义统一规则：

- 主面板和底部抽屉：16px 圆角；
- 输入和普通按钮：10px 圆角；
- 标签只在需要表达状态时使用胶囊形；
- 列表默认使用留白和单侧分隔线，不把每一项装进卡片。

### 4.4 图标

- 统一使用 Phosphor Icons；
- 同一层级统一线性或填充风格；
- 默认描边宽度 1.5；
- 图标按钮必须有中文无障碍名称；
- 不使用 Emoji、手绘 SVG 和混合图标库。

### 4.5 动效

动效只用于四类反馈：

- 页面前进和返回；
- 底部抽屉出现和消失；
- 任务开始、暂停和完成；
- AI 提案从草稿变为正式安排。

禁止滚动劫持、视差、持续漂浮和全屏粒子。每个页面最多突出 1-2 个动效。所有动效支持 `prefers-reduced-motion`，用户操作可以立即打断动画。

## 5. 前端技术栈

项目文档已经确定 Vite 和 React，前端按以下栈建立：

- React 19 + TypeScript；
- Vite；
- React Router，所有关键页面拥有独立 URL；
- Tailwind CSS v4，维护语义设计令牌；
- Radix Primitives，提供无障碍抽屉、对话框、菜单和切换控件；
- Motion，处理页面和状态过渡；
- Phosphor Icons，统一图标；
- TanStack Query，管理本地 API 状态；
- Zustand，只保存计时器、草稿和界面临时状态；
- React Hook Form + Zod，处理表单和校验；
- Vitest + Testing Library；
- Playwright，覆盖三条核心路径。

不引入完整主题组件库，不使用默认 shadcn 外观，也不同时混用多个设计系统。

## 8. 应用外壳

### 8.1 手机

- 顶部只保留页面标题和必要操作；
- 底部导航固定为“今天、目标、添加、我的”；
- 内容预留安全区域和底部导航高度；
- 页面主滚动区只有一个；
- 二级页面保留清晰返回路径；
- 抽屉打开后锁定背景滚动并管理焦点。

### 8.2 平板和桌面

- 1024px 以上将底部导航转换为窄侧栏；
- 内容最大宽度限制在 1180px；
- 今天页可采用主任务与时间轨迹双栏；
- 不增加桌面专属数据看板；
- 手机与桌面共享信息层级和业务路径。

## 9. 页面设计规划

### 9.1 载入今日

每日第一次打开显示短暂载入：人生状态、日期和一句行动提示。最多持续 1.2 秒，可跳过。关闭动效时直接显示最终状态。

### 9.2 今天

首屏顺序固定：

1. 日期和人生状态；
2. 当前焦点目标；
3. 今日唯一主线任务；
4. 接下来时间轨迹；
5. 待处理和冲突；
6. 添加任务和“发生了什么”。

首屏不展示总经验、复杂进度、全部领域和 AI 长文。

### 9.3 创建任务

第一层只展示标题、内容和时间。用户选择“更多设置”后再展开归属、步骤、结果要求、提醒和契约。

表单自动保存草稿。关闭未提交抽屉时先询问是否保留草稿。

### 9.4 AI 规划审阅

页面把“用户原始输入”和“AI 建议”分开显示。所有修改项按新增、移动、改变或警告标记。用户逐项编辑，最后统一确认。

AI 处理超过短暂等待时显示分阶段进度，不使用无说明的旋转图标。失败时保留输入并允许手动安排。

### 9.5 专注执行

隐藏主导航，只展示任务、当前步骤、计时器和四个操作：暂停、发生了什么、完成、结束。

计时状态必须在刷新后恢复。计时器使用等宽数字。任务开始后不显示奖励刷新入口。

### 9.6 完成与结果

普通任务使用短确认层完成，并显示基础经验。重要任务进入结果报告，用户填写产出、投入、自评和下一步。

AI 结算建议先预览经验、能力和里程碑变化。用户确认后才播放一次轻量结算动效。

### 9.7 待处理

待处理页不使用失败羞辱文案。每项明确展示原计划、当前事实和五种处理方式：改期、缩小、暂停、放弃、结束。

契约任务同时展示奖励失效、改期次数和应执行惩罚。

### 9.8 目标

目标首页显示五个领域和各自当前章节。章节详情以成功条件、目标和里程碑为主，不展示虚假百分比。

目标详情展示阶段、里程碑、关联任务和真实结果。AI 拆解从目标页触发，审阅方式与任务规划一致。

### 9.9 奖励与承诺

奖励卡只显示名称、成本、适用条件、免费刷新和改运次数。任务开始后切换为锁定状态。

惩罚兑现支持本地图片上传，并持续显示“图片只保存在本机”。身体类惩罚必须提供身体不适替换入口。

### 9.10 复盘

每日复盘控制在四个问题。每周复盘先呈现事实，再呈现 AI 解释和调整提案。所有提案逐项确认。

### 9.11 我的

“我的”只作为低频入口，包含成长、奖惩、复盘、长期记忆和设置。成长页保持简洁，不做游戏角色面板。

## 10. 状态设计

每个核心页面必须同时设计：

- 初次空白；
- 正常内容；
- 加载；
- AI 处理中；
- 网络或本地服务错误；
- AI 不可用；
- 数据冲突；
- 已完成；
- 权限受限，例如通知或图片权限未开启。

业务状态不依赖动画结束。快速连续点击必须取消旧动画并直接进入最新状态。

## 11. 数据接入策略

前端分两层接入数据：

### 11.1 体验仓库

先实现与真实 API 同结构的本地 Mock Repository，装入已经确认的职业、公众号、Agent 学习和健康示例数据。它用于快速完成视觉和交互验收，不在组件内写死数据。

### 11.2 真实仓库

本地 Node 服务和 SQLite 可用后，将 Repository 切换到 HTTP 实现。页面、领域模型和测试场景保持不变。

这样既能尽快体验完整前端，又不会把原型逻辑丢掉重写。

## 12. 实施阶段

### 阶段一：工程和设计系统

产物：

- 归档旧 HTML/CSS；
- 创建 React + TypeScript + Vite 工程；
- 建立路由、应用外壳、设计令牌和双主题；
- 完成按钮、输入、列表、抽屉、对话框和反馈组件；
- 建立 Mock Repository 和领域模型。

验收：375px、768px、1024px 和 1440px 均可正常显示；底部导航、安全区域、键盘焦点和主题切换有效。

### 阶段二：今天与普通任务闭环

产物：

- 载入今日；
- 今天页；
- 创建、编辑和删除任务；
- 普通任务开始、暂停、恢复和完成；
- 基础经验结算。

验收：第一条核心路径完整，刷新页面可以恢复模拟状态。

### 阶段三：AI 规划与现实中断

产物：

- AI 规划审阅；
- “发生了什么”；
- 调整提案；
- AI 加载、失败和手动降级状态。

验收：提案确认前正式任务不变化；拒绝提案后原计划保持不变。

### 阶段四：重要任务、奖励与失败处理

产物：

- 结果报告；
- AI 结算预览；
- 奖励生成、刷新和锁定；
- 契约确认；
- 待处理；
- 惩罚兑现和本地凭证。

验收：第二、三条核心路径完整；任务开始后不能刷新奖励；过期任务不会自动滚动。

### 阶段五：目标、复盘和长期信息

产物：

- 五领域、章节和目标详情；
- 阶段与里程碑；
- 每日和每周复盘；
- 成长档案；
- 长期记忆；
- 固定日程、通知和数据设置。

验收：用户可以从目标进入任务，也可以从结果回到里程碑；AI 记忆必须确认后生效。

### 阶段六：本地真实数据与 AI

产物：

- Node 本地服务；
- SQLite 数据库；
- DeepSeek V4 Flash；
- 图片目录；
- 导入、导出和恢复；
- 前端 Repository 切换到真实 API。

验收：清理浏览器缓存后数据仍在；API Key 不出现在浏览器；图片不进入 AI 请求；AI 断开后基础流程仍可使用。

### 阶段七：质量收口

产物：

- 三条 Playwright 核心路径；
- 业务规则单元测试；
- 空白、加载、错误和权限状态；
- 无障碍和键盘检查；
- 深浅主题、横屏和大字体检查；
- PWA 安装与本地通知；
- 性能和视觉清理。

验收：满足 MVP 页面验收清单，进入 14 天自用。

## 13. 测试矩阵

### 13.1 尺寸

- 375px 小屏手机；
- 390px 主设计宽度；
- 768px 平板；
- 1024px 横屏或小桌面；
- 1440px 桌面。

### 13.2 输入

- 触摸；
- 鼠标；
- 完整键盘操作；
- 屏幕阅读器基本路径；
- 大字体和中文长标题。

### 13.3 环境

- 深色和亮色；
- 减少动态效果；
- 本地服务关闭；
- DeepSeek 超时或错误；
- 浏览器刷新；
- 通知未授权；
- 图片上传失败；
- 空数据库和示例数据库。

## 14. 每阶段质量门槛

每个阶段结束前必须满足：

- 页面没有横向滚动；
- 所有点击目标至少 44×44px；
- 正文和关键图标达到 WCAG 对比度要求；
- 键盘焦点可见，顺序与视觉一致；
- 页面返回后恢复滚动、筛选和草稿；
- 主操作拥有即时按压或加载反馈；
- 空白、加载和错误状态存在；
- 动效支持减少动态效果；
- 页面内只有一个主要操作；
- 没有 Emoji 图标、AI 紫色、无意义玻璃和装饰性数据；
- 所有可见文案经过中文校对；
- 业务正确性不依赖动画。

## 15. 首轮体验验收顺序

不要等所有页面完成后一次验收。按以下节点在浏览器中体验：

1. 设计系统和今天页静态骨架；
2. 普通任务完整执行；
3. AI 规划和现实中断；
4. 结果、奖惩和待处理；
5. 目标、复盘和设置；
6. SQLite、DeepSeek 和备份接入；
7. 14 天自用版本。

每个节点只在上一节点的视觉和交互通过后继续，避免在错误方向上批量扩展页面。

## 16. 明确不做

本轮前端重构不继承旧视觉，不做营销首页，不做常驻 AI 聊天侧栏，不做人生全景大屏，不做复杂图表，不做社交，不做装备金币，不做滚动叙事，不做多套皮肤。

最终交付是一套能每天使用的个人任务产品，不是一张看起来功能很多的概念图。
