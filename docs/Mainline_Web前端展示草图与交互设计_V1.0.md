# Mainline Web 交互设计

**版本：V1.0**
**形态：移动端优先的本地 Web/PWA**
**语言：全中文**

## 1. 设计目标

Mainline 的界面应像一个安静的个人行动空间，而不是任务后台或游戏数据大屏。

首版遵循以下原则：

- 首屏只回答“现在做什么”；
- 一次只强调一个主要动作；
- 默认隐藏解释、统计和低频设置；
- 用留白、层级和短文案营造沉浸感；
- 游戏感来自章节、任务线、推进和结算，不来自满屏装饰；
- 所有业务文案使用中文，技术名词仅在设置或调试信息中出现；
- AI 建议与正式数据视觉上清楚区分；
- 危险、不可逆或涉及现实奖惩的操作必须再次确认。

## 2. 整体信息架构

移动端底部保留四个入口：

```text
今天    目标    ＋    我的
```

- 今天：查看并执行当日安排；
- 目标：查看领域、章节、目标线和里程碑；
- ＋：创建任务或记录“发生了什么”；
- 我的：成长、奖惩、复盘、记忆、备份和设置。

“成长”不单独占据底部导航，减少首页噪声。

## 3. 启动体验

每天第一次打开时显示 1～2 秒沉浸式载入：

```text
应届毕业后的过渡期

正在载入 8 月 14 日
今天只需要推进最重要的一步
```

随后自动进入“今天”。用户不需要确认晨间计划。当天再次打开时直接进入任务面板。

如果存在必须处理的过期任务，载入后先在顶部显示一个轻量提示，不使用全屏阻断。

## 4. 今天

### 4.1 页面结构

```text
┌─────────────────────────────┐
│ 8 月 14 日 · 周五           │
│ 应届毕业后的过渡期          │
│                             │
│ 当前焦点                    │
│ 适应工作 · 公众号持续输出   │
│                             │
│ ┌─────────────────────────┐ │
│ │ 今日主线               │ │
│ │ 完成登录模块接口联调   │ │
│ │ 10:00—11:30 · 90 分钟  │ │
│ │               开始任务 │ │
│ └─────────────────────────┘ │
│                             │
│ 接下来                      │
│ 14:00  修复反馈问题         │
│ 19:30  健身 45 分钟         │
│ 21:00  公众号文章初稿       │
│                             │
│ 待处理 2                    │
│                             │
│ [发生了什么]       [＋任务] │
└─────────────────────────────┘
```

### 4.2 信息顺序

1. 日期和人生状态；
2. 1～2 个当前焦点目标；
3. 唯一的今日主线任务；
4. 按时间排序的其他任务；
5. 待处理、冲突和临期提示；
6. 添加任务和“发生了什么”。

默认不显示总经验、全部领域、周统计、AI 长篇建议或完整日历。

### 4.3 任务卡片

任务卡片显示：

- 标题；
- 时间或期限；
- 所属目标的短标签；
- 状态；
- 是否有契约或结果报告。

右滑或长按提供改期、编辑、暂停和放弃。重要操作需要确认，普通完成可以直接点击。

## 5. 创建任务

点击中央“＋”后弹出两个大选项：

```text
安排一件事
告诉 Mainline 你准备做什么

发生了什么
记录刚刚出现的变化或干扰
```

### 5.1 快速录入

创建任务的首屏只要求：

- 标题；
- 内容；
- 希望什么时候完成。

底部操作：

- “直接保存”：用户自行安排；
- “请 AI 帮我规划”：进入 AI 建议。

### 5.2 AI 规划结果

AI 建议使用草稿样式，不能与正式任务混淆：

```text
AI 建议 · 尚未保存

推荐归属
学习 > Agent 开发能力

任务判断
支线目标 · 课程阶段 · 需要结果报告

建议拆分
1. 完成章节阅读，60 分钟
2. 运行示例并记录问题，45 分钟
3. 写一段复盘，20 分钟

时间安排
周六 09:30—11:35

风险
周六已有 5.5 小时安排，完成概率偏低。

[修改完整安排]    [确认保存]
```

用户可以展开并修改归属、步骤、时间、结果标准、提醒、奖励和契约。AI 不提供“一键偷偷应用”。

## 6. 发生了什么

这个入口服务于执行中的现实变化，不把所有生活记录都强行转成任务。

用户输入一段文字，并可选择影响：

- 打断当前任务；
- 影响今天安排；
- 可能影响目标；
- 仅记录。

AI 返回事件理解和建议：

```text
我理解为
临时工作打断了今晚的公众号写作。

建议
保留工作任务；将文章缩小为“完成提纲”，改到 21:40；
不建议挤压睡眠。

[只记录]    [编辑调整]    [确认调整]
```

用户确认前，系统不修改任何任务。

## 7. 专注执行

专注页面隐藏底部导航，只保留当前任务：

```text
完成登录模块接口联调

当前步骤
验证异常状态返回

        00:37:12

[暂停]          [完成]

发生了什么？
```

用户可在开始前选择正计时或番茄计时。任务开始后，契约奖励锁定，刷新入口消失。

暂停时提供原因快捷项：临时工作、他人请求、身体状态、短视频/游戏、环境、其他。用户也可以填写文字。

## 8. 完成

### 8.1 普通任务

一键完成后显示轻量反馈：

```text
已完成
+10 经验 · 工作交付能力 +6
```

动效不超过一秒，不使用持续遮挡页面的庆祝效果。

### 8.2 结果任务

结果报告使用单页表单：

- 做出了什么；
- 实际投入；
- 自评：低于预期、达到预期、超出预期；
- 下一步；
- 可选文字凭据说明。

AI 评估后展示建议：

```text
建议结算
+42 经验
工作独立交付能力 +28
沟通与协作 +14

里程碑进展
“独立完成一次完整交付”已推进

下一步建议
记录联调问题并整理成检查清单

[调整]    [确认结算]
```

用户确认后才写入经验和进展。

## 9. 待处理

过期或未完成任务集中进入待处理抽屉。每项必须选择：改期、缩小、暂停、放弃或结束。

存在契约时，页面同时显示：

- 原期限和规则；
- 剩余免费改期次数；
- 改期代价或到期惩罚；
- 兑现截止时间。

页面禁止使用羞辱性文案。它应明确事实和后果，例如：“任务已过期，奖励失效，需要处理已接受的承诺。”

## 10. 目标

### 10.1 领域总览

默认只显示五个领域及其当前章节：

```text
职业  从新人到独立承担工作      进行中
学习  AI Coding 与 Agent 能力    进行中
创作  公众号持续输出             当前焦点
健康  建立可持续训练节奏         进行中
生活  稳定过渡期生活             进行中
```

### 10.2 章节详情

章节页展示：

- 章节标题、时间与成功条件；
- 主线目标、最多两个支线目标；
- 阶段和里程碑；
- 当前真实进展；
- 最近结果记录；
- 暂停、结束和章节复盘。

进度条旁必须注明依据，例如“2/4 个里程碑完成”，不能用任务数量伪造百分比。

### 10.3 目标详情

目标页展示动机、成功条件、期限、预计投入、阶段、里程碑、当前任务和历史结果。AI 拆解入口放在目标内容下方，不做常驻聊天窗口。

## 11. 奖励与承诺

### 11.1 奖励生成

创建重要任务或里程碑时，AI 从批准的奖励池中生成候选：

```text
完成奖励
批准玩游戏 2 小时

免费刷新 1 次 · 改运次数 2/3
[换一个]    [接受奖励]
```

第一次刷新免费，之后消耗改运次数。开始任务后不再显示刷新按钮。

### 11.2 承诺确认

承诺页必须同时展示完成标准、期限、奖励、惩罚、改期规则和安全说明。用户需要主动勾选“我理解并接受”，才能生效。

### 11.3 兑现记录

惩罚兑现页面支持：

- 标记已兑现；
- 添加文字说明；
- 拍照或选择本地图片；
- 查看过去凭证。

页面明确提示：“图片只保存在本机，不会发送给 AI。”

## 12. 复盘

### 12.1 每日复盘

采用短流程，目标在一分钟内完成：

1. 今天真正推进了什么？
2. 最大的偏差是什么？
3. 当前状态如何？
4. 明天最值得推进什么？

系统自动列出未处理任务和待兑现奖惩。

### 12.2 每周复盘

周复盘展示事实，再展示 AI 解释：

- 各领域投入和里程碑变化；
- 计划与实际的时间差；
- 高频中断；
- 被跳过的日常任务；
- 奖惩兑现；
- 下周调整建议。

用户逐项接受或忽略建议。完成周复盘后补充 1 次改运次数，最多 3 次。

## 13. 我的

“我的”页面按低频程度组织：

- 成长档案；
- 奖励池与惩罚白名单；
- 每日/每周复盘；
- 长期记忆；
- 固定日程；
- 通知；
- 数据备份与恢复；
- AI 设置；
- 调试信息。

### 13.1 成长档案

只展示：总等级、经验、能力线、关键里程碑和历史轨迹。首版不展示金币、装备、血量、排行榜或复杂雷达图。

### 13.2 长期记忆

记忆按类别列出，支持查看来源、编辑和删除。AI 新记忆显示“待确认”状态。

## 14. 初始问卷

问卷采用一次一题或一组相关问题，顶部只显示简洁进度：

1. 你现在处于什么阶段；
2. 五个领域的现状；
3. 当前目标和必须做的事情；
4. 一周固定时间与精力；
5. 常见干扰；
6. 喜欢的奖励与预算；
7. 可接受的惩罚和安全限制；
8. 通知偏好；
9. AI 生成初始结构；
10. 用户审阅并开始。

问题可以跳过。连续跳过时提示会影响规划质量，但不阻止完成问卷。

## 15. 状态与异常

### 15.1 AI 处理中

使用明确进度文案，例如“正在检查时间冲突”“正在生成任务步骤”，允许取消。禁止只显示无限旋转动画。

### 15.2 AI 不可用

页面显示：“AI 暂时不可用，你仍可手动安排和完成任务。”所有基础功能保持可用，并提供重试。

### 15.3 空状态

空状态只引导一个动作。例如今天无任务时显示：“今天还没有安排。先决定一件最值得推进的事。”

### 15.4 本地服务未连接

明确区分本地服务关闭、数据库错误和网络 API 错误，给出可执行的恢复提示。

## 16. 视觉规范

- 深色或低饱和中性色作为主背景；
- 每个页面最多一个高亮主色；
- 主线使用稳定的强调色，警告只在真实风险处出现；
- 卡片减少边框和阴影，用间距建立层次；
- 标题短、字号明确，正文避免大段说明；
- 动效服务于载入、状态切换和结算，不持续干扰；
- 不使用满屏徽章、渐变、霓虹、排行榜和装饰图标；
- 触控目标不小于 44×44 像素；
- 重要状态不能只依赖颜色表达。

## 17. 响应式

首版按 390 像素左右的手机宽度设计。

- 小于 768 像素：单列、底部导航、全屏抽屉；
- 768～1199 像素：内容居中，可出现双栏目标详情；
- 1200 像素以上：最大内容宽度受限，可将低频导航放到左侧，但不能增加无用信息。

桌面端是手机体验的舒展版，不重新做一套复杂管理后台。

11. 领域总览；
12. 章节详情；
13. 目标详情；
14. 奖励与承诺；
