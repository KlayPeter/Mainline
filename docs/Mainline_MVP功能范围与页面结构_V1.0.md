# Mainline MVP 功能范围与页面结构

**版本：V1.0**
**状态：开发范围基线**
**目标：做出产品创建者愿意连续使用 14 天的本地版本**

## 1. MVP 定义

Mainline MVP 不是功能展示站，也不是完整人生管理平台。它必须真实跑通一条日常闭环：

```text
了解用户
→ 建立当前章节和目标
→ 安排今天的任务
→ 专注执行
→ 完成或处理失败
→ 结算奖励或惩罚
→ 复盘并调整下一步
```

判断一个功能是否进入 MVP，只看它是否直接支撑这条闭环。

## 2. 实现深度

首版功能分为三级：

### A 级：必须真实完整

用户每天会直接操作，必须使用真实数据并覆盖完整状态：

- 今日任务面板；
- 任务增删改查；
- AI 规划提案与用户确认；
- 任务开始、暂停、中断、恢复、完成；
- 普通完成和结果报告；
- 未完成任务处理；
- 奖励锁定和惩罚兑现；
- 每日复盘；
- SQLite 持久化。

### B 级：逻辑真实，界面从简

需要参与闭环，但首版不追求复杂交互或可视化：

- 初始问卷；
- 领域、章节、目标和里程碑管理；
- 固定日程；
- 能力线与经验记录；
- 每周复盘；
- 长期记忆管理；
- 凭证图片；
- 通知设置；
- 数据备份与恢复。

### C 级：首版不出现

- 账号、登录和云同步；
- 社交、排行榜和公会；
- 关系与财富领域；
- 装备、金币、战斗和商店；
- 复杂技能树；
- 月报、年报和大型数据看板；
- 原生 App、小程序和手表端；
- AI 图片审核；
- 多模型切换和第三方平台同步。

## 3. MVP 核心对象

首版只保留九类用户可感知对象：

| 对象 | 用途 | 首版限制 |
| --- | --- | --- |
| 人生状态 | 描述当前总体处境 | 同时只有一个当前状态 |
| 领域 | 分开经营不同生活方向 | 固定职业、学习、创作、健康、生活 |
| 章节 | 描述某领域的一段现实阶段 | 每领域最多一个当前章节 |
| 目标 | 定义阶段内想达到的结果 | 每领域最多一个主线、两个支线 |
| 里程碑 | 记录可验证进展 | 由结果推进，不按任务数计算 |
| 任务 | 每天实际执行的事情 | 同一天最多一个今日主线 |
| 结果 | 记录任务真正产生了什么 | 重要任务必须填写 |
| 契约 | 绑定奖励和惩罚 | 开始任务后锁定 |
| 复盘 | 从事实中调整下一步 | 每日和每周两种 |

阶段、能力线、经验账本、改运次数和长期记忆由系统维护，不在主导航中占据独立入口。

## 4. 导航结构

移动端底部只保留四个入口：

```text
今天        目标        ＋        我的
```

### 4.1 今天

默认首页，负责查看、开始和处理当天任务。

### 4.2 目标

查看领域、章节、目标、阶段和里程碑。

### 4.3 ＋

中央操作入口：

- 安排一件事；
- 发生了什么。

### 4.4 我的

收纳低频功能：复盘、成长、奖惩、长期记忆、固定日程、通知、数据和 AI 设置。

## 5. 页面地图

```text
启动
├── 初始问卷
│   └── 初始结构确认
└── 载入今日
    └── 今天
        ├── 任务详情/编辑
        ├── 专注执行
        │   ├── 记录中断
        │   └── 完成任务
        │       ├── 普通结算
        │       └── 结果报告
        ├── 待处理任务
        └── 今日复盘

中央 ＋
├── 安排一件事
│   └── AI 规划审阅
└── 发生了什么
    └── AI 调整审阅

目标
├── 五个领域
├── 章节详情
└── 目标详情
    └── AI 拆解审阅

我的
├── 复盘
│   ├── 每日
│   └── 每周
├── 成长档案
├── 奖励与承诺
├── 长期记忆
└── 设置
    ├── 固定日程
    ├── 通知
    ├── AI
    └── 数据备份
```

## 6. 页面优先级

### 6.1 核心页面

以下页面必须先形成完整交互：

| 编号 | 页面 | 核心任务 |
| --- | --- | --- |
| 01 | 今天 | 看清今天要做什么并开始行动 |
| 02 | 创建/编辑任务 | 录入真实任务，完成增删改查 |
| 03 | AI 规划审阅 | 审查分类、拆解、排程和契约 |
| 04 | 专注执行 | 计时、暂停、记录中断和完成 |
| 05 | 结果报告 | 记录重要任务的真实产出 |
| 06 | 待处理 | 明确处理未完成任务及后果 |
| 07 | 奖励与契约 | 确认、锁定、结算现实奖惩 |
| 08 | 每日复盘 | 结束当天并确定明天重点 |

### 6.2 支撑页面

以下页面使用简洁表单和列表即可：

| 编号 | 页面 | 最小能力 |
| --- | --- | --- |
| 09 | 初始问卷 | 收集现状、时间、目标、干扰和奖惩偏好 |
| 10 | 初始结构确认 | 修改并保存 AI 生成的章节和目标 |
| 11 | 领域总览 | 查看五个领域的当前章节和焦点 |
| 12 | 章节详情 | 查看成功条件、目标和里程碑 |
| 13 | 目标详情 | 查看阶段、任务和结果，触发 AI 拆解 |
| 14 | 每周复盘 | 查看真实统计并审阅 AI 调整建议 |
| 15 | 成长档案 | 查看经验、能力线和里程碑历史 |
| 16 | 长期记忆 | 查看、修改、确认和删除记忆 |
| 17 | 设置 | 管理固定日程、通知、AI 和数据 |

### 6.3 不单独建页的内容

- 经验结算：嵌入完成结果页；
- 改运次数：嵌入奖励卡片；
- 中断历史：嵌入任务详情和复盘；
- 里程碑结算：嵌入结果报告；
- 凭证上传：嵌入惩罚兑现；
- 通知记录：首版不提供通知中心；
- AI 对话：首版不做常驻聊天页。

## 7. 核心页面范围

### 7.1 今天

必须展示：

- 日期和当前人生状态；
- 1～2 个当前焦点目标；
- 唯一今日主线任务；
- 按时间排列的完整任务；
- 临期、冲突和待处理提示；
- “发生了什么”和“添加任务”。

必须操作：

- 开始、完成普通任务；
- 进入任务详情；
- 拖动或编辑时间；
- 处理待处理任务；
- 进入每日复盘。

首版不展示：周统计、全部属性、复杂日历、AI 长文和动态资讯。

### 7.2 创建/编辑任务

基础字段：

- 标题；
- 内容；
- 日期、时间段和期限；
- 预计时长；
- 所属目标；
- 行动形式；
- 日内优先级；
- 是否需要结果报告；
- 步骤、提醒和契约。

用户可以直接保存，也可以请求 AI 规划。编辑和删除必须真实写入 SQLite。

### 7.3 AI 规划审阅

AI 必须给出：

- 推荐归属和理由；
- 任务分类；
- 步骤和预计时长；
- 时间安排；
- 冲突与超载提示；
- 完成标准；
- 奖励和契约建议。

用户可以逐项修改、拒绝或确认。确认前不改变正式任务。

### 7.4 专注执行

必须支持：

- 正计时和番茄计时；
- 开始、暂停、恢复；
- 当前步骤；
- 记录中断；
- 完成或结束任务；
- 刷新页面后恢复进行中状态。

进入执行状态后，契约奖励禁止刷新。

### 7.5 结果报告

重要任务填写：产出、实际投入、自评和下一步。AI 可以建议经验、能力分配、里程碑进展和后续任务，用户确认后结算。

普通任务不进入该页面，直接按固定规则结算。

### 7.6 待处理

任务过期后不得自动移到明天。用户必须选择：

- 改期；
- 缩小或修改；
- 暂停；
- 放弃；
- 结束。

存在契约时同步显示奖励失效、免费改期次数、追加代价或正式惩罚。

### 7.7 奖励与契约

首版真实支持：

- 从批准的奖励池生成奖励；
- 首次免费刷新；
- 后续消耗改运次数；
- 开始任务后锁定；
- 金钱、权限和额外行动惩罚；
- 24 小时兑现期限；
- 本地图片凭证；
- 身体不适时替换身体类惩罚。

### 7.8 每日复盘

复盘控制在一分钟内：

1. 今天真正推进了什么；
2. 最大偏差；
3. 当前状态；
4. 明天最值得推进什么。

系统同时列出未处理任务和未兑现奖惩。

## 8. 支撑页面范围

### 8.1 初始问卷

首版只做一次完整问卷，不实现复杂的动态题库。用户可以返回修改、跳过问题和稍后补充。

问卷完成后，AI 生成初始结构草稿。没有 AI 时允许用户使用默认五领域并手动建立章节和目标。

### 8.2 目标结构

领域总览、章节详情和目标详情可以使用列表与折叠区，不需要图谱、地图或复杂技能树。

必须支持：

- 章节和目标增删改查；
- 当前焦点切换；
- 阶段与里程碑维护；
- 目标暂停、恢复和结束；
- 查看关联任务和结果。

### 8.3 每周复盘

确定性数据由系统计算：计划时间、实际时间、完成情况、中断类型、日常跳过和奖惩兑现。AI 负责解释和建议。用户逐项确认调整。

### 8.4 成长档案

只需展示：

- 总经验和等级；
- 能力线经验；
- 最近经验记录；
- 已完成里程碑；
- 简洁时间轨迹。

不实现经验消费、金币或装备。

### 8.5 长期记忆

使用分类列表展示已确认和待确认记忆。支持编辑、确认、删除和查看来源。

### 8.6 设置

设置页必须覆盖：

- 固定日程；
- 奖励池与预算；
- 惩罚白名单与安全限制；
- 通知开关和安静时间；
- DeepSeek 连接状态，密钥不在浏览器展示；
- 数据导出、校验和恢复；
- 本地服务与版本信息。

## 9. 首版完整演示数据

为了让首次体验具有真实内容，本地版本提供一套可重置的示例数据。

### 9.1 人生状态

“应届毕业后的过渡期”，持续 3～4 个月。

### 9.2 职业

- 章节：从职场新人到能够独立承担工作；
- 主线目标：建立独立工作能力；
- 成功条件：能独立承担工作并记录至少 3 次明确认可；
- 长期里程碑：年底争取调薪。

### 9.3 创作

- 目标：一个月发布 15 篇公众号内容，或新增 50 名以上关注者；
- 当前焦点：是；
- 示例任务：完成本周第一篇文章初稿。

### 9.4 学习

- 目标：完成 Agent 学习路线、项目和教学产出；
- 路线：SDD → Deep Agents → Hello-Agents → Agent-Learning-Hub → 完整项目；
- 示例任务：完成 Deep Agents 一个章节并运行示例。

### 9.5 健康

- 目标：建立可持续训练节奏；
- 示例日常：下班后健身 45 分钟；
- 允许跳过，频繁跳过后提出调整建议。

## 10. 三条必须跑通的体验路径

### 路径一：安排并完成普通任务

```text
今天 → 添加任务 → 手动保存 → 开始 → 暂停/恢复
→ 一键完成 → 获得基础经验 → 今天状态更新
```

### 路径二：AI 规划重要任务

```text
输入较大任务 → AI 分类和拆解 → 用户修改完整安排
→ 设置奖励与契约 → 确认 → 开始后锁定
→ 填写结果报告 → AI 建议结算 → 用户确认
→ 经验和里程碑更新
```

### 路径三：计划被现实打断

```text
执行任务 → 发生了什么 → 记录中断
→ AI 提出调整 → 用户确认或拒绝
→ 任务到期未完成 → 进入待处理
→ 改期/缩小/暂停/放弃/结束
→ 处理契约 → 每日复盘
```

## 11. 功能依赖

| 功能 | 依赖 |
| --- | --- |
| 今天 | 任务、固定日程、焦点目标 |
| AI 规划 | 用户输入、目标结构、日程、AI 提案 |
| 专注执行 | 任务状态、计时会话 |
| 结果报告 | 任务、完成标准、经验规则、里程碑 |
| 奖励契约 | 奖励池、改运账本、任务状态 |
| 待处理 | 期限检查、任务状态、契约规则 |
| 每日复盘 | 当日任务、中断、结果、奖惩 |
| 每周复盘 | 七日事实、目标进展、AI 提案 |
| 长期记忆 | 问卷、结果、复盘、用户确认 |
| 备份 | SQLite、本地图片目录 |

## 12. MVP 边界判断

遇到新增想法时，按以下顺序判断：

1. 它是否直接帮助用户今天开始或完成一件事？
2. 它是否补全执行失败后的处理？
3. 它是否让现实结果、奖惩或复盘更可信？
4. 删除它后，三条核心体验路径是否仍完整？

前三项都是否定，或删除后闭环仍完整，则不进入 MVP。

## 13. 页面验收

MVP 页面达到以下状态即可进入 14 天自用：

- 手机宽度下无需横向滚动；
- 首屏能在数秒内看懂今日主线和下一项任务；
- 所有主操作使用中文；
- 任务从创建到结算不存在断路或假按钮；
- AI 建议与正式数据能明确区分；
- AI 失败后仍能手动完成流程；
- 刷新页面不会丢失进行中任务；
- 过期任务不会自动消失或滚动；
- 奖励、惩罚、经验和改运次数可以追溯；
- 图片只在本机保存；
- 数据可完整导出和恢复；
- 页面没有无用统计、空洞文案和常驻 AI 聊天干扰。

## 14. MVP 完成定义

首版完成不以页面数量或视觉精细度判断。只有当用户能够用真实数据连续完成“安排—执行—结果—奖惩—复盘”，并在 14 天内愿意反复打开，MVP 才算成立。
